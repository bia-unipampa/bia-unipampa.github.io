Skills de IA para quem desenvolve software

Agentes de programação como Claude Code, Codex e GitHub Copilot escrevem código rápido, mas nem sempre o código certo. Skills são pequenos manuais em Markdown que ensinam ao agente um jeito disciplinado de trabalhar: entrevistar você antes de começar, escrever o teste antes do código, depurar com método. Este guia explica o conceito e mostra, passo a passo, como usar o repositório aberto mattpocock/skills, de Matt Pocock, educador conhecido pelos cursos de TypeScript.

1 · Conceito

Uma skill é um procedimento que o agente carrega quando precisa

Pense numa receita de bolo guardada na gaveta. O agente sabe que a receita existe (lê só o título e uma linha de descrição) e só abre a gaveta quando a tarefa pede. Isso mantém o contexto do modelo enxuto e torna o comportamento repetível: a mesma skill produz o mesmo método, sessão após sessão.

  • Uma pasta, um arquivo principal. Cada skill é uma pasta com um SKILL.md. Arquivos extras (exemplos, roteiros, scripts) ficam ao lado e são lidos sob demanda.
  • Cabeçalho YAML. O campo name dá o nome do comando; o description diz ao agente quando usar a skill. É a parte mais importante: uma descrição vaga faz a skill nunca ser acionada.
  • Corpo em Markdown. Instruções em linguagem natural, escritas para o modelo: passos, regras, antipadrões e o formato esperado da resposta.
  • Portável. O formato é texto puro, então a mesma skill funciona em vários agentes e modelos. Você pode ler, editar e versionar no git como qualquer código.
skills/productivity/grill-me/SKILL.md
---
name: grill-me
description: A relentless interview to sharpen a plan or design.
disable-model-invocation: true
---

Call the Skill tool with "grilling".

Esta é a skill inteira, copiada do repositório. Ela só pode ser acionada por você (disable-model-invocation: true) e delega todo o trabalho para outra skill, grilling, que contém o procedimento de entrevista. Skills pequenas e combináveis são a filosofia do repositório.

Skill, prompt, CLAUDE.md ou MCP?

RecursoQuando entra no contextoServe para
Prompt avulsoSó na mensagem em que você digitaPedidos pontuais; some na próxima sessão
CLAUDE.md / AGENTS.mdSempre, no início de toda sessãoRegras gerais do projeto (comandos de build, estilo, o que nunca fazer)
SkillSob demanda, quando a tarefa combina com a descrição ou quando você digita /nomeProcedimentos reutilizáveis: TDD, depuração, revisão de código, escrita de PR
Servidor MCPQuando o agente chama uma ferramenta exposta pelo servidorDar acesso a sistemas externos (banco de dados, issue tracker, navegador)

Regra prática: CLAUDE.md diz o que é verdade no projeto; uma skill diz como fazer um tipo de tarefa; MCP dá acesso a algo fora do computador.

2 · Por que existem

Quatro jeitos clássicos de um agente dar errado

O autor descreve o repositório como skills "para engenharia de verdade, não vibe coding". Cada grupo de skills ataca uma falha comum, apoiado em livros clássicos de engenharia de software.

Falha 1 · Desalinhamento

O agente não fez o que eu queria

Você acha que explicou bem; o agente entendeu outra coisa. A correção é uma sessão de perguntas antes de qualquer código.

"Ninguém sabe exatamente o que quer." Thomas e Hunt, The Pragmatic Programmer

Use: /grill-me e /grill-with-docs

Falha 2 · Prolixidade

O agente usa 20 palavras onde 1 bastaria

Sem um vocabulário comum, o agente descreve tudo por extenso. Um glossário do domínio (GLOSSARY.md) e registros de decisão (ADRs) criam uma linguagem compartilhada, como na Domain-Driven Design.

Antes: "o problema quando uma aula dentro de uma seção do curso ganha um lugar no sistema de arquivos". Depois: "o problema na cascata de materialização".

Use: /grill-with-docs e domain-modeling

Falha 3 · Código que não funciona

Alinhados, mas o resultado ainda quebra

Sem retorno sobre como o código roda, o agente trabalha às cegas. A saída são laços de retorno curtos: tipos estáticos, testes automatizados e o ciclo vermelho, verde, refatorar.

"A velocidade do retorno é o seu limite de velocidade." Thomas e Hunt

Use: tdd e diagnosing-bugs

Falha 4 · Bola de lama

O código cresce rápido e fica impossível de mudar

Agentes aceleram a escrita de código e, junto, a entropia. A resposta é cuidar do design todo dia, preferindo módulos profundos: muita funcionalidade atrás de uma interface simples.

"Os melhores módulos são profundos." John Ousterhout, A Philosophy of Software Design

Use: /improve-codebase-architecture e codebase-design

3 · Instalação

Três passos, uma vez por máquina e uma vez por repositório

Há dois modos de instalação. Como plugin, as skills se atualizam sozinhas. Pelo skills.sh, os arquivos são copiados para o seu projeto e você pode editá-los, mas atualiza à mão. Escolha um modo por agente: instalar os dois deixa cada skill duplicada.

  1. Instale as skills

    Escolha o seu agente abaixo e rode o comando correspondente no terminal.

  2. Configure o repositório

    Dentro do agente, rode /setup-matt-pocock-skills uma vez em cada projeto.

  3. Comece a usar

    Digite /grill-me ou /ask-matt e descreva o que você quer construir.

Passo 1: escolha o seu agente

Claude Code (atualização automática)
terminal
claude plugin install mattpocock-skills@claude-plugins-official
Codex (atualiza ao iniciar)
terminal
codex plugin marketplace add mattpocock/skills
codex plugin add mattpocock-skills@mattpocock
GitHub Copilot (CLI e VS Code)
terminal
copilot plugin marketplace add mattpocock/skills
copilot plugin install mattpocock-skills@mattpocock

Depois, uma única vez, acrescente ao arquivo ~/.copilot/settings.json para receber atualizações:

~/.copilot/settings.json
{
  "extraKnownMarketplaces": {
    "mattpocock": { "source": { "source": "github", "repo": "mattpocock/skills" }, "autoUpdate": true }
  }
}

No VS Code, use o comando Chat: Install Plugin From Source e informe https://github.com/mattpocock/skills.

Gemini CLI (atualização manual)
terminal
gemini skills install https://github.com/mattpocock/skills.git --path skills/engineering
gemini skills install https://github.com/mattpocock/skills.git --path skills/productivity

Para atualizar, rode os dois comandos de novo.

Cursor, OpenCode, Windsurf e outros (arquivos editáveis)
terminal
# agentes aceitos em -a: cursor, opencode, devin, windsurf, amp, pi
# sem -a, o instalador pergunta qual agente usar
npx skills@latest add mattpocock/skills -a cursor

Quando o instalador perguntar quais skills levar, inclua setup-matt-pocock-skills. Para atualizar, rode npx skills@latest update; para receber skills novas, rode o add de novo.

Passo 2: configure o projeto

Abra o agente na pasta do projeto e digite /setup-matt-pocock-skills. Ele faz três perguntas e grava as respostas no repositório, para que as outras skills saibam onde trabalhar:

Pergunta 1

Onde ficam as tarefas?

GitHub Issues, GitLab, arquivos locais ou outro sistema que você descrever. É para lá que /to-spec e /to-tickets publicam.

Pergunta 2

Quais rótulos de triagem?

Os rótulos que você aplica às tarefas (ex.: bug, needs-info). A skill /triage usa esses rótulos.

Pergunta 3

Onde salvar os documentos?

A pasta para o glossário do domínio, as ADRs e as especificações que as skills criarem.

Dica: confira o que foi gravado com git diff antes de commitar. As skills são texto; vale a pena lê-las, como você leria qualquer dependência que entra no projeto.

4 · Quem aciona

Skills que você chama e skills que o agente chama

O repositório divide as skills em um único eixo: quem pode acioná-las. Entender isso evita a frustração de esperar que o agente use sozinho algo que só você pode disparar.

Acionada pelo usuário

Você digita /nome

São orquestradoras: conduzem um processo inteiro, como uma entrevista, uma triagem ou a implementação de uma especificação. O cabeçalho tem disable-model-invocation: true, e a descrição é escrita para pessoas.

Exemplos: /grill-me, /to-spec, /implement, /handoff.

Acionada pelo modelo

O agente percebe que a tarefa combina

Guardam a disciplina reutilizável. A descrição traz frases-gatilho ("use quando o usuário pedir TDD, falar em vermelho-verde-refatorar...") para o agente reconhecer a situação. Você também pode chamá-las pelo nome.

Exemplos: tdd, diagnosing-bugs, code-review, grilling.

Regra de composição: uma skill acionada pelo usuário pode chamar skills acionadas pelo modelo, mas nunca outra skill acionada pelo usuário. Por isso /grill-me apenas diz "chame a ferramenta Skill com grilling".

5 · Catálogo

As skills do repositório, uma por uma

Filtre por área e por quem aciona. As skills de engenharia são para trabalho com código; as de produtividade servem para qualquer tarefa. Na dúvida sobre qual usar, comece por /ask-matt, que funciona como um roteador.

Área
Aciona

Descrições traduzidas e resumidas do README do repositório (novembro de 2026). O repositório também tem pastas misc, in-progress e deprecated, com skills experimentais ou antigas que não aparecem aqui.

6 · Fluxo de trabalho

Da ideia ao pull request

As skills foram desenhadas para se encaixar. Um fluxo típico para uma funcionalidade nova, do alinhamento à entrega, fica assim:

  1. /grill-with-docs

    O agente entrevista você, rodada por rodada, e atualiza o glossário e as ADRs.

  2. /to-spec

    Transforma a conversa numa especificação e a publica no gerenciador de tarefas.

  3. /to-tickets

    Quebra a especificação em tarefas pequenas, cada uma com suas dependências.

  4. /implement

    Constrói tarefa por tarefa, usando tdd nas fronteiras combinadas.

  5. code-review

    Revisa em dois eixos paralelos: padrões do projeto e fidelidade à especificação.

  6. pr

    Escreve a descrição do PR com resumo visual, evidência e risco da mudança.

Para bugs

Depurar com método

Descreva o sintoma. A skill diagnosing-bugs exige primeiro um laço de retorno que fique vermelho com o bug; depois, minimizar, levantar hipóteses, instrumentar, corrigir e deixar um teste de regressão.

Manutenção

Arquitetura a cada poucos dias

Rode /improve-codebase-architecture periodicamente. Ele procura oportunidades de aprofundar módulos e entrega um relatório em HTML; você escolhe uma e o agente o entrevista sobre ela.

Sessões longas

Passar o bastão

Quando a conversa ficar longa, /handoff resume o estado num documento para outro agente (ou você, amanhã) continuar sem perder contexto.

7 · Na prática

Como é uma rodada de /grill-me

A skill grilling organiza as decisões como uma árvore de projeto. Em cada rodada, o agente pergunta tudo o que já dá para decidir, numera as perguntas e sugere uma resposta. Você responde; a árvore avança. Exemplo ilustrativo:

Você/grill-me Quero adicionar login com Google no sistema de matrículas.
Agente · rodada 1 ❓ Q1, Contas existentes: alunos que já têm login por e-mail devem ter a conta vinculada automaticamente quando o e-mail do Google for o mesmo?
➡️ Recomendo: sim, vincular pelo e-mail verificado.

❓ Q2, Domínio: o login deve aceitar só contas institucionais (@unipampa.edu.br)?
➡️ Recomendo: sim, restringir ao domínio da universidade.
VocêSim para Q1. Para Q2, aceitar também e-mails pessoais de candidatos que ainda não são alunos.
Agente · rodada 2Essa resposta abriu novas decisões:
  • ❓ Q3: que permissões um candidato tem antes da matrícula?
  • ❓ Q4: quando o candidato vira aluno, a conta pessoal é migrada para a institucional?

Repare em três detalhes do procedimento: cada pergunta vem com uma recomendação (responder "sim" aceita a sugestão); perguntas que dependem de outras ainda abertas ficam para a rodada seguinte; e fatos que o agente pode descobrir sozinho (ler o código, consultar arquivos) ele mesmo busca, sem perguntar a você. O agente só começa a programar quando você confirmar que chegaram a um entendimento comum.

8 · Faça você mesmo

Adapte uma skill ou escreva a sua

O autor incentiva: "mexa nelas, faça delas suas". Como uma skill é só texto, criar a sua leva minutos. No Claude Code, skills pessoais ficam em ~/.claude/skills/ e as do projeto em .claude/skills/, versionadas com o código.

.claude/skills/migracao-banco/SKILL.md
---
name: migracao-banco
description: Cria migrações de banco de dados seguras. Use quando
  o usuário pedir para alterar o esquema, criar tabela ou coluna,
  ou mencionar "migração".
---

# Migração de banco

1. Leia o GLOSSARY.md para usar os nomes do domínio.
2. Gere a migração com `npm run db:new -- <nome>`.
3. Toda migração tem `up` e `down`. Nunca apague dados no `up`
   sem confirmar com o usuário.
4. Rode `npm run db:test` e mostre a saída antes de concluir.

## Antipadrões
- Editar uma migração que já foi aplicada em produção.
- Renomear coluna sem migrar os dados em duas etapas.
  1. A descrição é o gatilho. Diga o que a skill faz e quando usar, com as palavras que você realmente digita. Se ela for só acionada por você, escreva a descrição para humanos e adicione disable-model-invocation: true.
  2. Uma skill, um trabalho. Prefira skills pequenas que chamam outras ("chame a ferramenta Skill com tdd") a um arquivo gigante.
  3. Diga o porquê. Regras com motivo são seguidas com mais critério do que ordens em maiúsculas.
  4. Inclua o antipadrão. Mostrar o erro típico ajuda o modelo a evitá-lo.
  5. Detalhes vão para arquivos ao lado. Exemplos longos ficam em arquivos como tests.md, lidos só quando necessários, como faz a skill tdd.
  6. Teste e itere. Use a skill em tarefas reais e ajuste o texto quando o agente errar. Para escrever melhor, use a própria skill writing-for-agents do repositório.

Dúvidas frequentes

Antes de começar

Preciso pagar ou usar um modelo específico?

Não. O repositório é aberto e as skills funcionam com qualquer modelo. Você precisa apenas de um agente de programação compatível (Claude Code, Codex, Copilot, Gemini CLI, Cursor e outros), que pode ter custo próprio.

Skills substituem saber programar?

Não, e esse é o ponto. Elas codificam práticas de engenharia (testes, design de módulos, revisão, alinhamento de requisitos) que você precisa entender para avaliar o que o agente entrega. Quem conhece os fundamentos tira muito mais proveito delas.

É seguro instalar skills de terceiros?

Trate uma skill como qualquer dependência: ela muda o comportamento de um agente que pode editar arquivos e rodar comandos na sua máquina. Leia o conteúdo antes de instalar, prefira fontes conhecidas e revise as atualizações. O modo de arquivos editáveis facilita essa leitura.

Qual a diferença para frameworks como Spec-Kit ou BMAD?

Segundo o autor, esses frameworks assumem o controle do processo inteiro, o que dificulta corrigir quando algo dá errado. As skills de Matt Pocock são pequenas, independentes e combináveis: você usa só as que fazem sentido e adapta o resto.

A skill não foi acionada. O que fazer?

Verifique se ela é acionada pelo usuário (aí você precisa digitar /nome). Se for acionada pelo modelo, chame-a pelo nome ou reescreva o pedido com as palavras da descrição. Também confira se você não instalou o repositório duas vezes, por plugin e por skills.sh.
